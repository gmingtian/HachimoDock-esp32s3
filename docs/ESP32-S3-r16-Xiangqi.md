# 中国象棋：本地 r16 适配

当前交付状态：r16b 固件、中国象棋和配套桌面均已安装。21 组设备自动验收通过；桌面已观察到 r16b、已最新、按键配置一致、31 个组件，以及作者 gaomt 的离线象棋卡片。用户于 2026-11-08 确认实物“画面、引导和按键均正常”，本轮实物验收通过，保留 r16b。

## 玩法与操作

离线人机对弈，你执红先手。准备界面用摇杆上、下切换简单、普通、困难，默认普通。三档对应逐层加深的搜索，搜索分片运行，不一次占住整个操作循环。

| 操作 | 功能 |
| --- | --- |
| 摇杆四向 | 未选棋时移动光标；选棋后直接跳到该方向的合法落点 |
| 1 键 | 开始、选棋、落子；对局结束后重开 |
| 2 键 | 优先取消选棋；未选棋时撤回最近一轮红黑落子 |
| 3 键 | 使用现有全局退出功能 |

帅、仕、相、马、车、炮、兵全部提供合法落点引导。青绿色圆点代表可走的空位，橙红色圈表示可吃的对方棋子。选中位置、当前光标、最后一步另有标记。提示来自同一套 C 规则引擎，包含蹩马腿、塞象眼、炮架、过河、九宫、将帅照面及不能送将等限制。

支持将军、将死和无合法着法判负。属于休闲玩法，暂不实现竞赛级长将、长捉裁定。退出再打开开始新局，不保存未完成棋局。AI 搜索期间可以退出；悔棋会取消尚未提交的搜索结果。

## 固件、桌面和回滚

- S3 当前：`0.7.103-s3-r16b-80m-l320`，保留 80MHz SPI、原生 320×240 合成及 r15 动画处理。
- 固件 2,594,464 字节，SHA256：`b74735a501cc04fa8602c3cfa1f6b4e2ce2c11730ac004b0e979d7a88e80cb8a`，已从实际 OTA1 读回并比对。
- 本地桌面沿用版本号 `0.1.201`，增加象棋类型、三档状态投影和同一 C/WASM 引擎预览。它是本地适配版。
- 首次 r16 通过正式 OTA 写入 `ota_1`。r16b 为保留 r15 的 `ota_0`，先实际读回核对 r15，再用 USB 仅刷新现有 `ota_1`，未写分区表、启动选择数据或用户存储。启动有效、健康就绪、无待验证状态。
- 本地组件 `xiangqi-a4` 版本 `1.0.0`，作者 `gaomt`。通过正式组件安装事务，不涉及社区发布。

备份位于本机 `artifacts/a4-flash-backup/before-r16-full.bin`，包含个人设备数据，不作为公共游戏包分发。

## 验证记录

独立 C 核心通过 28,568 项断言及 MSVC AddressSanitizer 检查。原生包的正式 Rust 校验与图片编译已通过。S3 原生资源及升级保护回归 18 项通过。

首轮 OTA 首块回执超时后停止，未提交，随后确认 r15 仍为有效启动镜像，故障计数未增加。一次诊断事务测得首块总耗时约 187ms；第二次分离计时测得发送约 31ms、发送后的等待约 31ms，因此不能将 187ms 全部归因于设备写入。客户端旧窗口 150ms 对波动偏紧，新增 250ms 延迟回执回归并将上限调整为 1 秒。超时、未知结果仍终止，不自动重放或提交。

一项宽过滤运行包含的既有 Wi-Fi 集成测试因 fixture 缺少 `appearance transaction owner` 失败；与象棋和本次 USB 设备更新无关。不得把针对性测试结果描述为全仓库测试通过。

初版实机发现静态整张棋盘的重复绘制耗时约 240–290ms，挤占每轮 AI 分片：简单约 2.89 秒、普通约 19.09 秒、困难超过 30 秒。r16b 仅对 S3 横屏静态象棋界面跳过未变化的重复绘制，每秒仍强制刷新；页面、实例、公共状态变化或动态叠层会恢复刷新。规则、搜索深度和每片 256 work 上限均未降低。

同一开局，计时从最后一次落子命令发送前开始，到实际查询到回复为止：

| 难度 | r16b 实测 |
| --- | --- |
| 简单 | 619.80ms |
| 普通 | 1,038.19ms |
| 困难 | 4,597.86ms，包含每 800ms 一次公共脏键更新及 heartbeat 压力 |

这是固定开局的单次设备测量，局面变化会影响搜索量，不代表所有落子耗时上限。

21 组设备检查通过：七棋种/21 落点/71 动作的完整棋盘逐步比对，三难度回复与整轮悔棋，困难搜索期间退出，五次首页往返，以及五子棋、云端跳一跳、像素方块、蛙蛙养成打开后返回首页。首页还检查非重复 LCD 帧提交持续增长，不仅检查渲染计数。
