# S3 native home composition

User explicitly requested implementing native 320×240 composition after the r12 optimization. Scope is the landscape pet home, including its existing logical-coordinate overlays. Components keep the official 640×480 package contract. No input, codec quality, SPI frequency or resource limits change.

The current 320×240 I420 assets must convert directly to a clean native asset buffer. Compose on the existing alternating native output buffers. Raster primitives project logical even coordinates directly into native storage, reproducing the prior final nearest-neighbor sample without allocating or drawing a 640×480 home frame. Rectangles project clipped half-open bounds with ceil division. Existing local glyph paths use those primitives; host RLE glyphs need a scale-aware blitter. Queue cache and compact underlay must not read stale logical pixels during native composition. A separate 153600-byte PSRAM clean asset buffer prevents old overlays becoming part of the next frame while preparation is pending. Allocation failure uses the existing logical path.

Legacy non-2x assets and MJPEG retain logical conversion as a compatibility fallback before native overlays. Current full-size H264 assets must not write the logical frame. Components and square/P4 profiles retain existing rendering. Logical screenshot callers reconstruct a 2x logical view only on explicit access after a native frame. Approval, voice and session controls retain logical geometry and input behavior.

Acceptance: actual production primitive and converter tests compare native pixels against the prior logical result sampled at even coordinates, with guarded buffers, odd/clipped coordinates and dark edges. RLE blits preserve pin semantics and match the same reference. Completed-frame diagnostics report native composition and native asset conversion. IDF build, reviewed diff, backup preservation, same-scene device FPS and physical display feedback are required before claiming completion. Preserve r12 in OTA_1 and write candidate to OTA_0 only after backup/hash/partition verification. Never commit or publish.
