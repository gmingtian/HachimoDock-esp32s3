# 0.1.203 / S3 A4 r16d

目标硬件：ESP32-S3 N16R8、A4 三按键与四向可按下摇杆、ST7789 左排线 320×240 横屏。固件版本为 `0.7.103-s3-r16d-80m-l320`，客户端为 `0.1.203`。

## 修复

- Linux USB 扫描：识别 Espressif 原生 USB Serial/JTAG `303a:1001` 后保持运行时 DTR/RTS，避免扫描导致黑屏、复位或握手写入超时；其他适配器及 Windows/macOS 的控制线策略保持各自原有逻辑。
- 形象生成检查：桌面端通过本地 FFmpeg 提取首、中、末帧，避免 WebKitGTK 的视频画布噪点造成错误拒绝。媒体大小、时长、分辨率、外部引用和子进程执行时间均受限。已有生成视频继续保留；恢复任务不会自动重发结果未知的付费请求。
- S3 形象同步：原始二进制接收迁移到带存储作用域的接收 API，补齐 `raw-ready` 之后的分块完成回执，修复切换形象时同步中断。
- 会话状态：客户端转发与物理发送门禁都兼容同一 Agent 的裸会话 ID 和单层 `Agent:ID`，避免完成/休息消息被过滤。不同 Agent、不同会话和未提交跟随仍被隔离。
- 固件宿主测试：P4 原生 USB 上传测试明确提取 P4 实现，避免误用同一源文件中的 S3 空实现；补充真实超时清理断言，不修改 P4 运行时行为。

## 使用与验证范围

本机已验证 S3 r16d 启动有效、Linux USB 扫描连接、doudou 已有素材的完整事务提交，以及明确标记的临时测试会话“工作→完成→休息”的板端回执与诊断。临时测试会话不代表实际用户任务已经完成。三平台安装包的原生构建、资源和界面启动结果以本 Release 的 `Build-info.zip` 为准。

完整上游 P4 宿主套件在本版修改前已有失败：[基线 CI](https://github.com/gmingtian/HachimoDock-esp32s3/actions/runs/42636529079)记录 42 项失败及 34 项错误，包含 P4 渲染断言和测试夹具编译问题。本版不宣称完整 P4 套件通过；S3 直接相关回归、三平台客户端构建和发布包核对单独记录。

“9/13 个已有素材”表示当前形象的独立动作覆盖情况。两个可选左右触摸动作不属于默认生成动作；参考图被裁切而未生成的动作需要单独补齐，客户端不会把缺少动作伪装成已经生成。

首次改刷使用 factory 包；已有兼容 A4 布局使用 OTA 应用镜像。完整工厂刷写会替换配置和资源，应用升级用途不同。安装客户端不会自动刷机。本版沿用 80MHz、320×240 和原有引脚及分区；换屏、换线后的电气稳定性需按实物核验。15 fps 是素材上限，不是持续播放帧率承诺。

Windows x64 包未商业签名；macOS arm64 面向 Apple 芯片、macOS 13.5+，本地签名且未公证；Linux x86_64 面向 Ubuntu 24.04 基线，使用系统媒体与图形运行库。详细说明见[安装与恢复](INSTALLATION.md)、[兼容性](COMPATIBILITY.md)。

A4 PCB、R4.4 外壳和键帽文件沿用[上一版硬件附件](https://github.com/gmingtian/HachimoDock-esp32s3/releases/tag/v0.1.202-s3-a4-r16c)。原项目为 [YizhengWw/HachimoDock](https://github.com/YizhengWw/HachimoDock)，原作者 Yizheng Wang；原署名、许可证与第三方声明保留。
