# Firmware repair baseline

This folder remains based on PC-bundled 0.7.103, not the experimental 0.7.108 branch.

`main/pet_p4_miniapp.c` owns transactional component storage and per-component recovery from verified committed catalogs. Navigation persists only the last-opened ID, leaving the previous catalog available for recovery. Unparseable existing catalogs block destructive bootstrap reseeding. Known image-free bootstrap packages are distinguished from complete resources.

`main/pet_p4_protocol.c` exposes resource integrity and bounded resource-repair installation. Repairs retain component records and existing button configuration, and refuse writes during audio activity. `tools/build_builtin_bundle.py` emits bootstrap identity checks without inflating the bundle. `tests/component_resource_recovery_test.py` executes production recovery logic with sanitizers; fault injection belongs in offline tests, never on user storage.

S3 rendering uses the same component/game canvas with software JPEG/H264 conversion and a native 240×240 presentation boundary. `s3/pet_s3_render.h` owns tested integer aspect fit, bounded appearance policy (up to 15 fps, with legacy 10 fps compatibility) and canonical SPS validation before decoder allocation; `s3/pet_s3_renderer_ui.inc` keeps catalog/action navigation readable at native pixel size. `tools/prepare_s3_assets.py` converts prepared or source video trees into bounded target-tagged assets; `assets/s3-default` preserves all default appearance families. See `docs/superpowers/renderer-report.md` for memory budgets and validation limits.

S3 native home renders automatic session cards, two-line selected captions with
UTF-8-safe timed paging, recording feedback and a realtime/history view at 16px.
Chinese action names use package button labels plus bounded built-in fallbacks;
dispatch retains original IDs. The S3 PTT adapter respects realtime capture
ownership. `tests/s3_native_ui_test.py` executes production drawing and input code.

The S3 target keeps the same runtime modules and selects fixed-wiring backends in
`s3/` from the LCD/audio/input/touch/native-USB boundaries. Three real keys and a
software action/cursor menu expose component controls; hardware touch and vendor
USB stay unavailable. USB Serial/JTAG and USB-UART remain provisioning/recovery
transports; S3 additionally supports authenticated TLS Wi-Fi runtime control. Audio uses
independent I2S peripherals and conservative half-duplex conversation. See
`../docs/superpowers/hardware-report.md` for module tests and physical checks.

S3 release `0.7.103-s3-r3` adds `s3/pet_s3_wifi.c` (STA, NVS identity, bounded TLS
I/O and DNS-SD) plus `s3/pet_s3_protocol.inc` (serialized ingress, immutable
connection generations, lease and disconnect cleanup). Portable framing/lease
helpers and executable host tests cover stale input, raw-block isolation, busy
switching, auth ordering, audio route pinning and local-menu confirmation. See
`s3/README-wifi.md` for wire endpoints, memory/time limits and hardware-test gaps.

S3 component policy is defined in `s3/component-policy.json` and mirrored by the
host-checked `pet_s3_component_policy.h`. Four built-in games that need controls
beyond the three physical keys are hidden from existing catalogs, rejected at
installation and skipped by embedded bootstrap. Stored packages and saves are
preserved. `tools/build_s3_factory.py` derives 25 S3 defaults from the unchanged
29-component P4 configuration. This is a reviewed built-in list, not a generic
capability classifier for custom applications.

S3 recovery accepts read-only legacy USB hello probes and resets malformed
non-owner USB framing without touching the active Wi-Fi stream. Transport busy
checks include accepted capture requests and playback streams still buffering,
so release, takeover and network-menu changes wait for the entire audio session.

S3 r4 fixes physical-board boot failures. `s3/pet_s3_json_memory.h` installs
PSRAM-only cJSON allocation once at entry, before any JSON or worker task exists;
JSON exhaustion stays recoverable instead of draining the internal RTOS/libc heap.
Catalog text/binary reads yield one tick even on missing files, allowing IDLE0
to run while restoring all 25 packages. S3 r4 uses 128-byte USB writes: IDF 6.1 console startup installs a 256-byte
TX ring before app_main, so init_usb preserves that smaller driver.
`tests/s3_boot_runtime_test.py` exercises the real bundle allocator (including
OOM cleanup), file lookup bursts and 12 KiB USB messages with partial writes.
See `../docs/ESP32-S3-BOOT-FIX.md` for decoded evidence and hardware verification.

Current distribution resets to 0.7.103-s3-r1, retaining the historical r4 fixes.

`PET_S3_DISPLAY_PROFILE=landscape-left` selects the optional ST7789 320×240
output with FPC on the left, original 640×480 layout at half scale and the same
three-key menus. `s3/pet_s3_display.h` is the common source for LCD geometry,
rotation and hello physical dimensions; square remains the default. The build
script isolates outputs and never overwrites the bundled square image for this
profile. See `../docs/ESP32-S3-Landscape.md` and `tests/s3_landscape_test.py`.

Landscape panel feedback corrected orientation by 180 degrees: swapXY=1,
mirrorX=1, mirrorY=0. Geometry, original UI layout and square profile are unchanged.

Landscape bundles all 16 native 320×240/15fps pet animations in
`assets/s3-landscape-default`, encoded from original MP4s with Lanczos/CRF 27.
`assets/s3-landscape-source.json` records the input family/audio mapping.
The factory builder selects this pack only for landscape; square retains its
240×180 pack and limits. Runtime SPS/catalog bounds and hello appearance size
use the selected profile, while landscape still accepts legacy 240×180 packs.
S3 CPU video conversion reuses source pixels/rows with pixel-equivalence tests,
clears only letterboxes, and reports CPU conversion timing. Only idle pet pixels
whose RGB channels are all <=12/255 become pure black, suppressing near-black
compression blocks before UI overlays. Tests cover padded I420, both profiles,
all shipped streams, package identity/capacity and actual FFmpeg encoding.
No physical frame-rate claim follows from host tests or conversion counts.

The component-center early-return optimization is square-profile-only.
Landscape executes the original card renderer; executable tests cover all
catalog sizes/focus positions to prevent a blank background-only page.

Landscape component-center typography preserves the original card/background/icon
geometry, using doubled logical detail fonts for ~16px output. Captions move
slightly within each card; concise three-key hints replace touch/joystick copy.
The active badge retains its small original geometry/font. Executable rendering
tests compare all non-text commands against the original launcher.

Landscape global typography promotes legacy scale-1 text through the existing
24px medium rasterizer, with matching width/bounds/UTF-8 clipping. Integer area
filtering in 2x2 groups preserves thin strokes under the final half-scale pass.
Graphic labels locally raise font/line height within their original clip;
source-font bounds and package nodes remain unchanged. Executable regression
coverage is in `tests/s3_typography_test.py`.

Both package font atlases and LVGL fallback glyphs also average source coverage
for each final 2x2 logical cell, constrained to the original node clip. Tests
exercise every thin row/column at both pixel phases through the real rasterizer.

Landscape UI assets are derived by `tools/prepare_s3_ui_assets.py` into
`assets/s3-landscape-ui`: 25 packages, 64 component images/font atlases,
26 art thumbnails, one launcher background and two instrument layers. Native
320×240 backgrounds use JPEG 95/4:4:4; small art is Lanczos-sized to its original
physical box, tile-by-tile. Font grids/metrics stay original with exact A8 palette
coverage; vector icons integrate source coverage into native pixels. Generation
needs Pillow; build checks only SHA256 via the Python standard library.
CMake and `tools/build_s3_factory.py` select these resources for landscape only.
`tools/p4_component_sprites.py` accepts an explicit cache root; the default shared
factory path and canonical packages are unchanged. Native JPEGs pass bounded
`pet_p4_image.h`/surface guards and expand exactly 2× before composition.
Landscape total palette indices increase by 4KiB to accommodate radio art;
single-image bounds remain unchanged. Tests execute all 25 layouts, 64 decoders,
native/full-size JPEG composition, exact controls/metrics and vector coverage.
The complete factory package replaces pictures; application-only updates do not.
