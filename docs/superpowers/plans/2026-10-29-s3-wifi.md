# ESP32-S3 USB / Wi-Fi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add authenticated, encrypted Wi-Fi with the complete existing S3 USB runtime feature set, remembered preference and safe USB fallback.

**Architecture:** Share existing JSONL/binary transactions over USB and TLS. A device lease and connection generation isolate owners. Network I/O has a single owner and bounded queues; business code retains current request IDs, checksums and commit rules.

**Tech Stack:** ESP-IDF 6.1 C/FreeRTOS/esp_wifi/esp-tls/mDNS, Rust/rustls, Tauri/React, C host tests, Rust integration tests and Node tests.

**Spec:** docs/superpowers/specs/2026-10-29-s3-wifi-design.md

## Global Constraints

- Existing N16R8 wiring and three keys stay unchanged; P4 remains target-isolated.
- TLS 1.2 minimum; service TCP port 48973; mDNS `_hachimodock._tcp`.
- Initial USB provisioning; per-board certificate and random 32-byte credential; credentials never enter logs.
- Certificate trust is device-specific; do not modify system trust or disable TLS verification.
- One active control owner; immutable generation on every queued request and reply.
- First use USB, remember explicit choice, never steal a live connection; after Wi-Fi loss clean transactions before bound-board USB fallback.
- No direct switch during audio, resource sync or OTA; never replay a user action or failed transfer.
- TLS and authentication deadlines 5 seconds each; host lease 6 seconds; JSON line buffer 32768 bytes; outbound budget 128KiB; send deadline 1 second.
- Keep two 3MiB app slots and current resource partitions. No physical verification claims without a board.

## Shared wire contract

All maintenance requests use JSONL `{topic,payload}` with a unique `requestId`.
Every response echoes it; failure has `ok:false,error:<non-secret-code>`.

- `wifi/status` -> `wifi/status`: `ok,enabled,configured,connected,ssid,ip,rssi,port,boardDeviceId`.
- `wifi/scan` -> `wifi/scan`: `ok,networks:[{ssid,rssi,secure}]`, bounded to 20 entries.
- `wifi/configure` -> `wifi/status`: input `ssid,password,enabled:true`. USB-only.
- `wifi/pair` -> `wifi/pair`: USB-only response `ok,boardDeviceId,hostname,certificatePem,token,ip,port`. Private key never leaves firmware. Reuses existing token until revoked.
- `wifi/set_enabled` -> `wifi/status`: input `enabled`.
- `wifi/clear` -> `wifi/status`: USB-only; clears configuration and revokes credentials after safely closing the old network session.
- `transport/release` -> `transport/status`: current owner explicitly releases only if no active operation.
- First TLS application request is `wifi/auth`: `token,desktopDeviceId,expectedBoardDeviceId,takeover:false,requestId`. `takeover:true` is only for an explicit user switch; reject while busy. Reply `wifi/auth`: `ok,boardDeviceId,requestId` before any normal hello/events.
- Once authenticated and leased, reuse all existing JSONL requests and raw asset blocks unchanged. Hello advertises `capabilities.transport.wifi:true,wifiProtocol:"pet-wifi-tls-v1"`, `usbOnly:false` for S3.
- Valid certificate SAN hostname is `<boardDeviceId>.local`, used independently of current IP.
