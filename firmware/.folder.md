# Firmware repair baseline

This folder remains based on PC-bundled 0.7.103, not the experimental 0.7.108 branch.

`main/pet_p4_miniapp.c` owns transactional component storage and per-component recovery from verified committed catalogs. Navigation persists only the last-opened ID, leaving the previous catalog available for recovery. Unparseable existing catalogs block destructive bootstrap reseeding. Known image-free bootstrap packages are distinguished from complete resources.

`main/pet_p4_protocol.c` exposes resource integrity and bounded resource-repair installation. Repairs retain component records and existing button configuration, and refuse writes during audio activity. `tools/build_builtin_bundle.py` emits bootstrap identity checks without inflating the bundle. `tests/component_resource_recovery_test.py` executes production recovery logic with sanitizers; fault injection belongs in offline tests, never on user storage.

S3 rendering uses the same component/game canvas with software JPEG/H264 conversion and a native 240×240 presentation boundary. `s3/pet_s3_render.h` owns tested integer aspect fit, bounded appearance policy and canonical SPS validation before decoder allocation; `s3/pet_s3_renderer_ui.inc` keeps catalog/action navigation readable at native pixel size. `tools/prepare_s3_assets.py` converts prepared or source video trees into bounded target-tagged assets; `assets/s3-default` preserves all default appearance families. See `docs/superpowers/renderer-report.md` for memory budgets and validation limits.

S3 native home renders automatic session cards, two-line selected captions with
UTF-8-safe timed paging, recording feedback and a realtime/history view at 16px.
Chinese action names use package button labels plus bounded built-in fallbacks;
dispatch retains original IDs. The S3 PTT adapter respects realtime capture
ownership. `tests/s3_native_ui_test.py` executes production drawing and input code.

The S3 target keeps the same runtime modules and selects fixed-wiring backends in
`s3/` from the LCD/audio/input/touch/native-USB boundaries. Three real keys and a
software action/cursor menu expose component controls; hardware touch and vendor
USB stay unavailable, and USB Serial/JTAG remains the transport. Audio uses
independent I2S peripherals and conservative half-duplex conversation. See
`../docs/superpowers/hardware-report.md` for module tests and physical checks.
