# ESP32-S3 USB / Wi-Fi 双通道设计

状态：用户于 2026-10-29 批准实施，连接优先级按下述补充执行。

## 目标

沿用现有 ESP32-S3 N16R8、ST7789 240×240、I2S 音频和 GPIO39 / 38 / 0
三键接线，为 Windows、Apple 芯片 macOS 和 Linux 客户端增加局域网连接。
Wi-Fi 覆盖当前 S3 USB 的运行时功能，USB 继续承担首次安装、配网和恢复。
原有的显示、存储和半双工音频限制不因连接方式改变。

## 方案选择

推荐使用 TLS 加密的 TCP 字节流，复用既有 JSONL、二进制资源块和请求回执。
现有固件的协议工作队列、资源和 OTA 校验继续作为唯一业务执行入口。

比较方案：

| 方案 | 收益 | 代价 |
|---|---|---|
| TLS + 原协议字节流（推荐） | 运行时功能可共用，二进制块不需要再编码 | 增加连接归属、TLS 和缓冲管理 |
| WebSocket + 原协议 | 以后容易提供浏览器入口 | 当前客户端为原生应用，额外增加帧封装和依赖 |
| 独立 HTTP 业务接口 | 单个接口容易调试 | 语音和双向事件需另做通道，USB/Wi-Fi 功能容易分叉 |

## 首次配网与绑定

1. 用户先安装新版固件并通过 USB 连接客户端，在设备页面打开“Wi-Fi 设置”。
2. 固件扫描 2.4GHz 网络，客户端填写 SSID / 密码；允许手动输入隐藏网络。
   密码只经当前 USB 连接交给设备，客户端不长期保存路由器密码。
3. 设备生成自身 TLS 身份和独立的高熵连接凭据，存入 NVS。
   公共证书、板端 ID 和连接凭据通过已连接的 USB 提供给客户端。
   TLS 私钥留在设备，证书不加入操作系统全局信任库。
4. 客户端将板端身份、公开证书和地址关联保存，连接凭据存入现有平台凭据存储。
   其他电脑通过 USB 增加绑定；不要求公网账号或云服务。
5. 配网成功后显示 SSID、IP、信号和连接状态。用户可主动切换到 Wi-Fi，
   此后设备只需 USB 供电，电脑无需连接该数据线。

无线连接先完成 TLS 证书及板端身份核对，再进行客户端凭据认证。
最低使用 TLS 1.2；凭据为设备随机生成的 32 字节，比较时采用常量时间实现。
USB 增加绑定复用当前凭据；菜单执行“撤销所有无线绑定”时轮换凭据，
使其他电脑已保存的凭据立即失效。清除配网会同时停止无线会话并删除网络配置。
未认证连接不能订阅音频、下发状态、读写资源或升级固件。
发现信息不包含 Wi-Fi 密码、TLS 私钥或连接凭据。
日志、诊断和发布附件不得包含上述秘密。

设备菜单提供 Wi-Fi 状态、启停和带确认的清除配网；保留三键既有短按与长按动作。
未配网、密码错误、路由器离线、凭据已清除均有明确中文状态，USB 可继续使用。
初版不增加手机配网页面、常开开放热点或远程公网访问。

## 发现与重连

设备服务端口为 48973，mDNS 类型为 `_hachimodock._tcp`，实例使用板端 ID。
客户端通过 mDNS 找到已绑定的板端；
保留手动填写 IP 的入口，用于禁用组播或发现失败的网络。
发现结果只用于寻找地址，不能代替 TLS 身份校验。
设备仅加入用户配置的局域网；不做 UPnP、端口映射或扫描任意网段。

路由器断开后退避重连；IP 改变后重新发现。客户端记住用户选择的连接方式，
后台 USB 探测不得抢占有效的 Wi-Fi 连接。设备仍有有效活动连接时，不因
接入另一根数据线或第二台电脑而无提示切换控制权。

首次连接默认 USB；成功手动选择后持久化 USB / Wi-Fi 偏好。
当前连接有效时不自动切走，包括偏好 Wi-Fi 时后台重新发现 USB。
Wi-Fi 断线后先清理当前事务，再尝试同一绑定板端的 USB；恢复无线后不抢占
已经回退成功的 USB。录音、同步、升级期间不直接自动切换，失败的操作
不得自动重放。后台探测只能连接已绑定的设备。

## 单一控制权与事务边界

同一时刻只有一个运行时控制连接，可以为 UART、USB Serial/JTAG 或 Wi-Fi。
USB 配网和状态查询属于维护入口，不能绕过活动资源或升级事务。
显式切换在空闲时进行；录音、播放或传输期间提示停止当前操作后切换。
设备租约失效时取消旧会话，清理未提交传输，然后才接受新的控制连接。
沿用现有 6 秒宿主心跳租期；TLS 握手和应用认证各最多等待 5 秒。

每条连接具有独立且单调变化的 generation。协议队列请求、延迟回执、
异步事件和输出缓冲都绑定 generation；新连接不能收到旧连接的音频或回执。
仅按传输类型路由不足以保证隔离，不能复用可变全局 reply_ctx 代表旧请求。
未获得控制权的 USB 输入不能进入全局二进制资源块解析器。

资源与 OTA 沿用现有校验及最后提交机制。断线不得自动重放按钮动作或
写入请求；清理后由用户重新发起传输。固件升级成功重启后重新发现原板端，
仅在设备报告校验成功时显示升级完成，不以客户端发送完毕作为成功。

## 固件实现边界

- S3 专用网络模块负责 Wi-Fi 生命周期、NVS、发现、TLS 认证和 socket。
  P4 继续编译既有传输，不默认引入 S3 无线依赖。
- 共享协议入口接收来源身份和 generation；USB / Wi-Fi 共用协议工作队列。
- 网络任务独占 TLS 对象；音频、按键和协议工作任务只写入有界发送队列，
  不在全局传输锁或运行状态锁内等待网络读写。
- 短写、粘包、分包、超长行和半截二进制块有明确处理；队列满或发送超时
  结束当前连接，不静默丢弃协议块、不把剩余块误当新 JSON 请求。
  JSON 行沿用 32768 字节缓冲上限；网络待发数据最多 128KiB，队列字节数和
  条目数均有界，单次发送等待最多 1 秒。超限断线后释放队列及当前传输。
- Wi-Fi 无客户端连接时不积累音频与状态。连接数限制为一个已认证会话，
  TLS 握手和认证均有超时。为显示、I2S、协议和 Wi-Fi 预留内部 RAM。
- 优先将大型业务缓冲放 PSRAM，网络缓冲有固定预算。保持现有 16MiB 分区；
  必须检查新增应用仍能放入两个 3MiB OTA 槽以及 NVS 剩余容量。

## 客户端实现边界

当前 UsbSerialManager 已共用事务、回执、板端身份和写入接口。
提取可测试的连接安装与读循环，增加显式 transport 类型，保留现有 Tauri
命令兼容性，业务发送不依赖虚构的串口名或波特率来识别 Wi-Fi。

网络连接由单一 I/O 任务拥有 TLS 流，通过有界队列与共享业务层交互，
避免 TLS 读锁阻断录音回执或写入锁阻断接收。移除仅串口适用的节流条件
对 Wi-Fi 的影响，同时保留 S3 Flash 写入回执和设备公布的资源块上限。

设备页面增加 USB / Wi-Fi 选择、配网、发现、手动 IP、连接状态与清除绑定。
统一设备在线判断、状态转发、音频、组件数据、形象与固件升级路径；
连接提示按实际通道显示。原 USB 接口命名的兼容保留不应泄漏为用户界面限制。
无线控制仍由本机客户端接入 Agent、ASR 和 TTS 服务，服务配置继续由电脑管理。

## 功能验收范围

| 功能 | USB | Wi-Fi 目标 |
|---|---|---|
| 桌宠状态、会话气泡、切换与额度 | 保留 | 同一协议与效果 |
| 三键事件、配置、组件操作 | 保留 | 双向收发，无重复动作 |
| 按住录音、语音对话、播报、音乐 | 保留 | 同一半双工能力与会话隔离 |
| 默认/自定义形象、组件与资源管理 | 保留 | 完整同步、校验、取消和失败清理 |
| 固件应用 OTA、诊断与截图 | 保留 | 完整协议路径、升级后身份重连 |
| 首次刷完整镜像、ROM 下载模式、启动日志 | 保留 | 继续使用 USB，尚无无线运行时可供连接 |
| 清除配网与切换电脑 | 保留 | 菜单或 USB 维护入口可操作 |

## 验证与交付

先用失败测试覆盖连接归属、过期 generation、原始资源块隔离、认证拒绝、
短写、分包、超时、断线重连、取消以及升级重启。客户端用本地 TLS 模拟
设备跑共享事务，包括组件、形象、双向音频与固件；不能只验证普通状态消息。
固件保留 host tests 并完成真实 ESP-IDF S3 构建、分区和内存检查；
客户端完成 Linux 检查及 Windows / macOS 原生 CI 构建和打包检查。

测速使用同一资源文件和校验结果，区分原生 USB Serial/JTAG 与 USB-UART；
记录总耗时、有效吞吐、信号强度、失败次数和语音中断情况。理论总线速率、
波特率和无线 PHY 速率均不能作为实测下载速度。

本板尚未连接，射频、信号、音频欠载、显示帧率、掉电恢复和持续稳定性必须
另做实机测试。交付中区分已实现、模拟测试、构建检查和实机结果。
不覆盖现有 r2 下载：无线版更新版本号并提供独立预发布固件和三平台客户端。
