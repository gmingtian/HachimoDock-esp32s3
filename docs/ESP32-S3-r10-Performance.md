# ESP32-S3 A4 r10 渲染优化与实机验收

2026-11-07。在官方 0.1.201 A4 适配版上继续优化，固件为 `0.7.103-s3-r10-l320`；桌面程序版本仍为 0.1.201。未提交、推送或发布 Git 更改。

## 本轮改动

- 组件中心按真实可见内容保存少量元数据：数量、页、选择、加载态及四张卡片的 ID、标题、活动状态与资源状态。相同内容复用上一幅成功提交的画面，同时保留正确的 LCD 缓冲索引。
- 同页选择或卡片内容变化时，只恢复并重画受影响的卡片区域，完整恢复圆角和阴影下方背景。翻页、数量变化、加载态变化和不可靠的上一帧仍完整重画。
- 页面切换、审批遮罩及遮罩退出、实时模式变化、传输画面、播放复位或 LCD 提交失败均不能复用旧画面。
- S3 横屏的椭圆改为按扫描行填充，保留原整数椭圆的像素判定及裁切；减少逐像素 64 位计算。P4 与 S3 方屏保持原路径。

没有新增像素帧缓冲，没有提高 SPI 时钟，没有降低素材分辨率、画质或帧率。组件缓存只存元数据；组件中心函数编译栈占用由 272 增至 736 字节，主渲染函数仍为 400 字节，主任务栈为 16,384 字节。按钮引脚、16 项绑定及输入模型不变。

## 实机结果

设备 `A4-test-device`，COM3，同一块 320×240 A4 焊接板。统计值来自设备内部渲染计时，不是主机请求耗时。

| 场景 | r9 | r10 |
|---|---:|---:|
| 组件中心静止，100 帧窗口 P95 | 161.122 ms | 0.711 ms |
| 同窗口最后一帧 | 152.524 ms | 0.450 ms |
| 同窗口最大值 | 162.232 ms | 0.790 ms |
| 内部空闲堆 | 45,507 B | 45,443 B |
| 连续同页切换，最后一个窗口 P95 | 未取得有效对照 | 83.914 ms |

连续切换通过 `widget/select_by_id` 完成，约每 0.7 秒一次，共 34 次；同时每 0.3 秒查询诊断，最后窗口最大值为 112.055 ms。脚本保存并恢复原组件选择和页面。静止窗口采样约 42 秒，每 2 秒查询诊断；窗口已经覆盖 100 帧。

静止页面现在省去重复绘制、缩放和 LCD 比较工作。这不表示屏幕达到数百 FPS，也不能把该结果推广成宠物动画帧率提升。本轮没有修改 H264 解码器；主页面、组件游戏、录音和云语音并非都做了专项性能基准。

## 校验与验证范围

- 生产椭圆/圆角函数的数学像素边界与裁切检查通过，包括退化椭圆。
- 生产组件中心函数的局部绘制与完整绘制逐像素比较通过，覆盖 0–28 个项目、翻页、内容/标题/活动态/资源态更新、加载状态、缺失条目，以及背景恢复。字形/缩略图输入在主机测试中使用确定性图案；未宣称实机截图逐像素比较完成。
- 两项渲染回归通过；同一真实绘制测试程序经 Windows MSVC AddressSanitizer 运行通过。原本补充的 Linux 源码传输被自动审批拒绝，没有外传源码，改用本机内存检查。
- 实际 ESP-IDF 6.1 编译通过，应用 2,580,080 字节，3 MiB OTA 分区余量约 18%。
- 配套资源回归 20 项通过、2 项跳过；实际安装目录 292 个资源校验及真实 320×240 / 15 帧转换、解码通过。
- r10 运行和启动分区均为 OTA_1，`runtimeReady=true`、`pendingVerify=false`。本次直接选择 OTA 分区后 `imageState=undefined`，未将其写成 OTA 状态 `valid` 或声称完成自动回滚验收。
- 实机读回 A4 模型及 16 项绑定，摇杆就绪，输入丢包为 0，音频采集/播放接口就绪；桌面端显示设备与内置固件均为 r10、配置已同步、总音量读回 100%。这不等于实际麦克风录音验收。

r9 的截图基线请求出现超时，期间累计历史故障计数由 0 增至 1，未据此宣称截图成功。随后 r10 静止、连续切换及再次启动的该计数均保持为 1，最后复位原因 USB、`lastResetWasFault=false`。补做 r9 连续切换对照时也遇到串口写入超时，未取得有效数据；恢复步骤始终将启动分区切回 r10，之后已通过实际查询和客户端界面确认。
