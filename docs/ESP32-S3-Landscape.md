# ESP32-S3 · ST7789 240×320 左排线横屏

适用于原有 ESP32-S3 N16R8 接线，屏幕更换为 ST7789 240×320。
正面看屏幕时，FPC 排线在左侧，输出为 320×240 横屏。
使用控制器的交换 XY 与 X 镜像，零偏移。根据本屏实机反馈，已将首版横屏方向再旋转 180°；不同模块的原生扫描方向仍需实机确认。

主页、会话卡片、组件中心和组件共用原版 640×480 画布，按 1/2 缩小铺满屏幕。
三键的动作菜单、组件附加操作和软件光标保留；菜单宽度适配 320 像素。
横屏预置的全部 16 组宠物动画使用 320×240、15fps，由原始高清视频直接缩小编码，
不是由旧版 240×180 放大。继续兼容已有 240×180 形象。单段 384KiB、形象槽 3MiB
的容量限制保持原值；方屏仍使用旧素材和旧尺寸上限。这不是保证达到 15fps 的性能声明。

## 构建

```sh
HACHIMO_S3_DISPLAY_PROFILE=landscape-left bash firmware/tools/build_s3.sh
python3 firmware/tools/package_s3_release.py \
  --factory artifacts/s3-landscape-left/hachimodock-s3-factory.bin \
  --app artifacts/s3-landscape-left/hachimodock-s3-app.bin \
  --display-profile landscape-left \
  --output artifacts/s3-landscape-left/HachimoDock-S3-320x240-left_Factory.zip \
  --upgrade-output artifacts/s3-landscape-left/HachimoDock-S3-320x240-left_App.bin
```

使用独立构建目录和输出目录；不替换客户端内置的方屏固件。
固件版本 `0.7.103-s3-r6-l320`，应用工程名仍为 `pet_manager_s3_runtime`。
hello 的逻辑画布为 640×480，物理输出报告为 320×240。
默认 `square` 构建仍为原 240×240 中文布局。

## 刷入

已有设备优先通过客户端手动选择横屏应用镜像升级，以保留配网、形象和配置。
若使用串口烧录应用，先确认活动分区：`ota_0` 地址 `0x10000`，`ota_1` 地址 `0x310000`。
不可把应用镜像写到 `0x0`，也不要在保留数据升级时整片擦除。
完整包中的 `hachimodock-s3-factory.bin` 用于 `0x0` 完整刷机，会替换资源和配置。
主机测试和编译不能验证屏幕实际旋转方向、颜色或完整硬件性能；刷入后需确认四角和文字方向。

修正组件中心：仅方屏使用原生列表覆盖；横屏执行原版卡片绘制，避免只显示黄色背景。

## 组件中心文字可读性

保留原版四宫格、背景、卡片和图标的全部绘制几何。标题保持原字号；
数量标记、卡片说明、编号和操作提示采用双倍逻辑字号，半尺寸输出后
保留约 16 像素字形。说明文字在卡片内部略微上移并使用更深颜色；长文
沿用截断省略，不换行撑开卡片。小型“已打开”徽标保持原尺寸和字号。
提示改为实际三键操作，避免显示摇杆/触屏说明。

## 全局文字可读性

横屏普通界面及旧版组件文字统一将小字号由 16 逻辑像素提升到 24，
对应约 12 屏幕像素；原有大标题及组件中心已优化的约 16 像素文字保留。
文字宽度、居中、换行/省略使用同一套字形度量。24 像素字形按面积采样，
让单像素细笔画在最终半尺寸输出后仍可见，不需要新增整屏缓冲区。

图形组件包的文字节点同样设置 24 逻辑像素目标下限，并限制在原节点
高度内；窄小徽标可能只能达到约 9–10 屏幕像素，以避免裁切和覆盖相邻
控件。组件自带字体图集及通用字库回退也按最终屏幕像素覆盖范围进行面积采样，
保留缩屏前的细笔画。图标、背景、布局与操作热区不修改。此策略不会改变图片素材本身
已经画入的文字；它只能处理固件和组件节点绘制的文字。

## 原生动画与渲染优化

横屏资源位于 `firmware/assets/s3-landscape-default`；源清单是
`firmware/assets/s3-landscape-source.json`，输入为 `pc/public/terrier-clips` 的
原始 MP4（例如待机视频为 854×480），保留原有音效与全部行为。
使用 Lanczos 缩放、H264 constrained baseline、单参考帧、单 slice、CRF 27
重新编码。相较旧版 CRF 30 减轻压缩；不会为了容量自动降帧或再降低画质。

```sh
python3 firmware/tools/prepare_s3_assets.py \
  --source firmware/assets/s3-landscape-source.json \
  --app-data-dir pc/public/terrier-clips \
  --output firmware/assets/s3-landscape-default \
  --width 320 --height 240 --fps 15 --crf 27
```

S3 的 I420 → RGB565 路径复用相同源像素及扫描行，预计算横向采样位置；
只清除画面外的黑边，避免先清整屏再覆盖。320×240 动画每帧颜色转换从
307,200 次降至 76,800 次，保留原颜色公式、采样坐标及合成布局。
除待机清黑外，主机逐像素测试验证与旧路径一致；没有新增整屏缓冲。
CPU 转换时间也计入串口 `P4 render perf ... convert=...` 日志。

默认动画的近黑压缩残留会显示成微弱灰绿块。仅 S3 待机行为（`idle`、`idle.*`）
在合成文字前，将输出 RGB 三通道均不超过 12/255 的像素置为纯黑。
这会压掉该极暗范围内的细微层次；其余颜色、非待机动画和组件画面保留。

应用升级包只更换程序，不会替换设备已有的形象资源。完整刷机包包含全部
320×240 新素材，写入 `0x0` 会替换资源和配置。桌面端原有的 240×180 转码
仍可使用，但以后从旧客户端重新同步形象会装回该分辨率；此次没有发布新客户端。

没有对这版固件进行实机帧率测量。15fps 是素材规格，需通过设备串口性能日志
及提交帧计数测量实际播放效果，不能把计算量减少比例当作帧率提升比例。

## 全部小组件图片适配

`firmware/tools/prepare_s3_ui_assets.py` 从原版组件包 PNG、组件中心原背景及
木鱼原始透明图生成独立的 `firmware/assets/s3-landscape-ui`。覆盖当前 25 个
内置小组件：64 张内容图片/字体图集、26 张有效组件中心缩略图、1 张组件
中心背景、2 张木鱼/木槌透明图层，总计 93 项；没有图片的页面保留程序绘图。

全屏背景为原生 320×240 JPEG（质量 95、4:4:4）；内容装饰、旋转唱片按原
显示区域的一半尺寸重采样，拼图逐格处理，避免相邻图块颜色串入。
图标不拉伸到整屏。组件中心缩略图为 32×24，圆角与卡片位置不变。
木鱼/木槌图层为 160×122、80×82，仍使用原始逻辑设计框定位和缩放。
38 张字体图集保留原格尺寸和度量，重新编码为精确 A8 覆盖的白色调色板，
由上一版的最终像素面积采样绘制，避免再次缩小字体源导致笔画损失。
20 种矢量按钮图标在最终像素范围平均原有线条覆盖，保持图形与原边界。

```sh
PYTHONPATH=/path/to/pillow python3 firmware/tools/prepare_s3_ui_assets.py
python3 firmware/tools/prepare_s3_ui_assets.py --check
```

生成需要 Pillow；构建只运行标准库的源/输出 SHA256 检查。工厂打包仅横屏
选择独立组件 JSON/PNG/编译缓存，P4 和方屏的原包、原图片保持原样。
全部页面元素、字体度量和按钮 JSON 与原包逐项比较，位置与操作区域不变。
JPEG 在共用画布上以 2×恢复，最终半尺寸显示可保留每个原生像素。
城市电台的原生背景加唱片需要 99,904 个索引像素，横屏总缓存仅增加 4KiB
至 102,400；单图、打包容量及旧图解码边界继续受检查。

应使用本轮完整刷机包才能替换所有旧组件资源。仅应用升级保留设备已存
组件，无法自动替换图片；旧客户端重新安装内置组件也可能换回原版资源。
这批资源经过主机解析/解码和完整工厂包验证，仍需设备确认颜色、动画与
字体显示。刷新目标继续为普通页面 20 次/秒、指定动态页面约 30 次/秒，
这不构成实机帧率保证。
